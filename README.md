# ru-planets-and-more

Сборный мод русской локализации для Factorio 2.0.
Отображаемое название: **«Перевод модов: планеты и не только»**.

Один пакет вместо десятка разрозненных правок: кладёт свои `locale/ru/*.cfg`
поверх оригинальных модов через необязательные зависимости, ничего в них
не изменяя.

## С чего начать

Из внешнего нужен только Python 3 — сторонних библиотек скрипты не требуют.

Проверить, что всё на месте:

```bash
python3 tools/check.py
```

Ожидаемый ответ: `ВСЁ ЧИСТО`, дальше — число файлов, зависимостей и версия.

## Типовые задачи

**Собрать исходники чужих модов для сверки**

```bash
python3 tools/sources.py          # собрать из установленных модов + отчёт
python3 tools/sources.py --list   # только отчёт
```

Кладёт `locale/en` и `locale/ru` каждого установленного мода
в `../original_mods` — вне репозитория — и показывает, по каким модам
из зависимостей исходников нет.

Скачивать архивы скриптом нельзя: страницы загрузки портала стоят за
Cloudflare и отдают 403 любому клиенту, кроме браузера и самой игры.
Недостающие моды ставятся через игру (Моды → Установить, включать
не обязательно), после чего скрипт подхватит их из папки модов.

**Добавить новый мод в пакет**

1. Положите `locale/en/*.cfg` мода (и `locale/ru/*.cfg`, если перевод уже есть)
   в `source-en/` — без английского оригинала сверка невозможна.
2. `python3 tools/gaps.py source-en/EN.cfg [source-en/RU.cfg]` — увидеть объём.
3. Перевести в `mod/locale/ru/<имя-мода>.cfg`.
4. `python3 tools/audit.py` — сверить получившееся с оригиналом.
5. Дописать `? modname` в `mod/info.json` и запись в `reference/listing.json`;
   без второго сборка не пройдёт.

**Проверить существующий перевод**

```bash
python3 tools/audit.py source-en/EN.cfg source-en/RU.cfg "Название мода"
```

**Собрать релиз**

```bash
python3 tools/build.py
```

Архив появится в `dist/`. Сборка сама запускает проверку и прервётся,
если что-то не так.

## Что где лежит

| Путь | Что это |
|---|---|
| `mod/` | Сам мод, то что уходит в архив |
| `tools/` | Скрипты: sources, gaps, audit, check, listing, build, publish |
| `source-en/` | Оригинальные файлы модов для сверки |
| `docs/GLOSSARY.md` | Устоявшиеся переводы терминов |
| `docs/PITFALLS.md` | Грабли, на которые уже наступали |
| `docs/STATUS.md` | Таблица покрытия и что осталось |
| `reference/` | Полная карточка страницы мода на портале |
| `dist/` | Собранные архивы |

## Публикация

Мод опубликован: https://mods.factorio.com/mod/ru-planets-and-more
Менять `name` в `info.json` уже нельзя — это равносильно созданию нового
мода с потерей истории и подписчиков.

### Вручную

```bash
python3 tools/build.py            # архив + карточка + поля для API
python3 tools/publish.py          # вхолостую: покажет, что уйдёт
python3 tools/publish.py --all --yes
```

`--all` — и тексты страницы, и архив. По отдельности: `--details` (только
`summary`, `description`, `faq`) или `--release` (только архив). Тексты
перезаписываются сколько угодно; архив под уже занятым номером версии портал
не примет, пока предыдущий не удалён вручную на странице мода.

Отдельного поля Changelog на портале нет — вкладку он строит сам из
`changelog.txt` внутри архива.

Ключ портала берётся из переменной окружения `FACTORIO_API_KEY` либо из
`~/.factorio-api-key`. **В репозитории ключа быть не должно.**

### Через GitHub Actions

| Workflow | Когда | Что делает |
|---|---|---|
| `.github/workflows/check.yml` | каждый пуш и PR | проверка, сборка, архив в артефактах |
| `.github/workflows/release.yml` | тег `v*` или вручную | сборка, публикация на портал, GitHub Release |

Нужен секрет **`FACTORIO_API_KEY`** в окружении `portal`
(Settings → Environments → portal) с правами `ModPortal: Upload Mods`
и `ModPortal: Edit Mods`.

Выпуск версии:

```bash
git tag v1.11.0 && git push origin v1.11.0
```

Тег обязан совпадать с версией в `mod/info.json` — иначе workflow остановится
до отправки. Запуск вручную даёт выбор: `all`, `details`, `release`
или `dry-run`.
